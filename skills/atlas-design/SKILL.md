# Atlas Design — Token System, Contrast, & Archetype Diversity

Read `design-brief.md` and `.atlas-direction.json` (generated by [deal-direction.mjs](../../scripts/deal-direction.mjs)), then define tokens in `design-tokens.css` referencing [design-tokens.css](../../templates/design-tokens.css) and the visual asset rules in [imagery.md](../../references/imagery.md).

## 1. Ban the Uniform Frame ("2-Column Hero + Filter Workbench Card")

Never force the *"2-column hero on the left + search/filter/Reset workbench card on the right + alternating bands"* frame onto every site, because doing so turns restaurants, event posters, and portfolios into recolored SaaS clones. Follow `dealtPrimaryDirection.macroLayout` from `.atlas-direction.json`:

| Project Domain | Required Macro Layout Structure | Forbidden Patterns |
|---|---|---|
| **Restaurant / Café / Culinary** | **Full-Bleed Atmospheric Cover + Hours/Address Bar + Two-Column Print Menu Ledger** | Do not place search inputs/filter dropdowns in the hero or small abstract line charts. |
| **Event / Symposium / Festival** | **Full-Width Swiss Typographic Poster (Oversized Date/Venue) + Speaker Grid & Chronological Schedule** | Do not use a SaaS 2-column hero or tiny sparse arc diagrams surrounded by whitespace. |
| **Photographer / Architect Portfolio** | **Minimal Top Colophon + Asymmetric Exhibition Plate Grid (16:9 & 4:5) + Footer Biography** | Do not place search/select/Reset toolbars above curated work. |
| **Nonprofit / Donation / Annual Report** | **Single-Column Editorial Dossier (68ch) + Margin Callouts + Allocation Chart & Audit Table** | Do not use an operational dashboard shell or filter toolbar at the top. |
| **E-Commerce / Physical Product** | **Multi-Angle Product Gallery Stage (60%) + Variant Selector & Measured Spec Table (40%)** | Do not place a data-table search toolbar on a single-product page. |
| **Operational / Financial Dashboard** | **Full-Viewport App Shell (Left Rail + KPI Strip + Dense Filterable Data Table + Detail Drawer)** | Do not add large promotional marketing hero banners above the workspace. |
| **Developer Documentation** | **Three-Pane Portal (Left Nav Tree + 68ch Guide & Code Tabs + Right On-This-Page Rail)** | Do not use promotional landing-page marketing layouts. |
| **Wedding / Legal / Education** | **Centered Ceremonial Crest & Timeline** (Wedding), **Numbered Practice Matrix** (Legal), **Weekly Syllabus Track** (Education) | Do not mix SaaS pricing widgets or filter dashboards into ceremonial or advisory pages. |

## 2. WCAG AA Contrast, Typography Cap, & Rich Visual Proof

1. **WCAG AA Contrast Compliance:** Ensure every foreground/background token pair in `design-tokens.css` achieves at least `4.5:1` contrast (`3.0:1` for qualifying large text) so content stays crisp and legible.
2. **Max 2 Proportional Font Families (+ 1 Optional Monospace):** Declare at most 2 proportional font families (display & body) plus 1 optional monospace family for numerals/code in `design-tokens.css`.
3. **Imagery & Real/Generated Raster Asset Strategy:** Follow the decision tree in [imagery.md](../../references/imagery.md): (a) use real user assets when provided; (b) if a photography-dependent domain lacks photos, **generate bespoke images** (`image-generator` / `generate_image`) into `assets/images/` or **fetch real licensed photography** (`node <atlas>/scripts/fetch-photos.mjs`) into `assets/photos/`, marked silently with `data-photo-slot="..."` and `data-atlas-proof="generated-image"` / `"real-photography"`. **Never** draw manual `<svg>` scenes/floorplans as a substitute for photography, and **never** render visible placeholder text (`"Replace with photo"`, `"PHOTO SLOT 01"`, or hill-and-sun SVG silhouettes) in visitor UI.

## Verification Commands

Run `node <atlas>/scripts/check-tokens.mjs <project-root> --tokens <token-file>` and `node <atlas>/scripts/check-visual-proof.mjs <project-root>`.
