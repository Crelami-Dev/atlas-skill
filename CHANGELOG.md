## Unreleased — Lessons from the Atlas vs Taste build comparison

### Phones and tablets (reported: scenes did not move on mobile; tablet portrait looked messy)
- **Motion now runs on every device.** `atlas-scenes.mjs` has four modes (`<html data-atlas-motion>`): `scrub` (>= 1024 px, pinned scroll-driven scenes as before), **`play` (below 1024 px: every scene plays once, smoothly, when 15% of it is on screen, about 1.7 s, no pinning)**, `soft` (reduced motion: opacity-only fades at 15%, scenes finished) and `rest` (Anime.js unavailable). Before, heavy scenes stayed completely still below 768 px and reduced motion switched everything off. Scenes over the pinned budget on desktop now play instead of sitting still. CSS gained an `.is-play` state.
- **Slower, smoother defaults:** reveal 1250 ms (was 920), hero 1100 ms, stagger 110 ms, `ease: 'outQuart'`; docs say `1100-1600 ms` everywhere (was 850-1050 ms). The 15% rule is the same on every device (a section starts when 15% of the screen height of it is visible).
- **New components (`templates/atlas-components.css`, `atlas-interact.mjs`):** `.atlas-card` (+ media, lift), **`.atlas-carousel`** (swipe row with a peeking next card, arrows, dots (up to 5 slides, then a counter), keyboard, ARIA roles; `--grid-up` becomes a 2-column grid on tablet portrait with the odd last card as a horizontal card and 3-4 columns on desktop; `--always`, `--wide`) and **`.atlas-bento`** (mosaic gallery: 2 columns below 1024 px, 4 above; feature, wide, tall, text and accent tiles; no text over photos). `initAtlasCarousels()` is exported and called by `initAtlasInteract()`.
- **`references/mobile-and-tablet.md`:** size bands (phone / tablet portrait / desktop), a content-to-pattern table (cards, galleries, steps, figures, tables, forms, nav), the "why does my phone look static" checklist, and the motion table. SKILL.md, `phase-workflow.md`, `visual-review.md`, `atlas-frontend`, `atlas-motion-animejs`, `atlas-ui-architecture`, `scenes.md` and `creative-direction.md` point to it.
- **`quick-check.mjs`:** audits 600 and 768 px (tablet portrait) and adds `mobile-long-stack` (3+ picture cards stacked past 1.8 screens) and `half-empty-row` (a picture filling part of its row with nothing beside it at 600-1023 px). Run on the latest Atlas-built Nirwana site they flag exactly the lone 480 px picture at 600/768/820 px and the long stack at 320 px. `self-test.mjs` now 31 cases.
- **Demo and tests:** `templates/atlas-patterns-demo.html`; `tests/small-screens.test.mjs` (real browser at 375, 768 and 1440 px: modes, the 15% gate holds the start pose then plays to the end, reduced motion, carousel swipe/dots/keyboard, 2 and 3 columns, bento columns and overflow; skipped when no browser or CDN).

- **Fixed after a Codex review of this work:** scenes and reveals now start only when the real 15% is visible (the first observer callback can fire for a sliver, e.g. after a reload that restores scroll); carousel previous/next step by position and no longer stick at the end of a multi-slide track; carousel slide offsets were wrongly shifted by the track's own page offset (broke stepping on centred desktop layouts); dots are 44 px targets with a counter past 5 slides; `initAtlasCarousels().destroy()` removes its controls and ready marker so it can run again; the browser suite probes for real Playwright and skips on the CDP fallback. `small-screens.test.mjs` now has 8 browser cases.

- **Self-playing loops (`atlas-loops.mjs` + `.css`, `references/loops.md`, `templates/atlas-loops-demo.html`).** The pattern asked for: a mini demo that types a line, runs a progress bar, brings in rows and chips, shows a result, holds, resets and replays (`[data-loop]`, plus an inverted terminal variant), rotating words with no layout shift (`[data-rotate]`), a seamless ticker (`[data-marquee]`), a CSS-only ambient layer (`.atlas-fx`) and a page-level pause (`[data-loops-toggle]`). Rules built in: starts at 15% visible, pauses off screen, a 44 px pause button per demo or ticker, a user's pause survives scrolling away and back, reduced motion shows the finished frame, first word or a wrapping row. `quick-check.mjs` adds `loop-no-pause` (self-moving content with no pause control). `tests/loops.test.mjs` proves it in a real browser (typing, rows, reset and replay, off-screen pause, pause button, global toggle, reduced motion, rotator width, ticker). `self-test.mjs` is now 33 cases.

- **Fixed after a Codex review of the loops:** ambient layers (`.atlas-fx`, `.atlas-float`) now obey the page-level pause and cannot restart while paused; rotators and ambient layers get an automatic floating pause toggle when the page has none (`loop-no-pause` now also covers them); short tickers repeat until each scrolling half covers the viewport and re-layout on resize (no jump at the loop point); typed lines keep an invisible copy of the finished text in the same grid cell so a card never changes height when a long line wraps; the caret stops blinking when paused; hover and focus holds on tickers are independent; the loops handle exposes `animated` so tests skip cleanly when Anime.js is unavailable. Found by the new tests along the way: ticker copies duplicated element ids, now stripped (copies are also hidden from assistive tech and out of the tab order). `tests/loops.test.mjs` now has 12 browser cases.

### Earlier in this release

- **`quick-check.mjs`:** new `mobile-nav-missing` (FAIL at >= 3 hidden header links with no menu control at <= 820px, WARN at 2), `dead-space` (WARN, desktop sections whose content ends far above their bottom edge) and `partial-opacity` (WARN, elements still translucent 2s after a reveal at mid/low scroll). `mobile-nav-missing` accepts separate visible mobile markup that reaches the same destinations, and only counts a control that operates the hidden navigation (`aria-controls` target, `aria-expanded`, `summary`, or checkbox `label`), so an unrelated theme or search button cannot mask a missing menu (both gaps found by a Codex review). Four new `self-test.mjs` regression cases cover the new checks (22 total).
- **`fetch-photos.mjs` no longer hangs.** The old `timeout` only fired on socket silence, so a server trickling bytes (or a stalled download) could block the run indefinitely. Now: a hard wall-clock limit per request (`--request-timeout`, default 30s), a total budget (`--timeout`, default 120s), one retry for transient errors (timeouts, 429, 5xx), per-query error isolation (a failed search no longer cancels the others), a 30 MB response cap, and `credits.json` rewritten after every download so an interrupted run never leaves unattributed photos. Result status is now `ok`, `partial` (some skips or budget hit), `no-matches`, `offline-fallback` (every search failed) or `error`, with a `problems` list. `ATLAS_WIKIMEDIA_API` overrides the API URL for tests. New `tests/fetch-photos.test.mjs` (5 cases) uses a local server that trickles forever.
- **`references/imagery.md` section 1b:** photo relevance rules beyond licensing: hero shows the business's own subject, local-context match, subject-first queries, resolution floor, drop weak frames, optional context photo for evidence panels, per-image fit note in `## Image plan`.
- **`references/visual-review.md` and `phase-workflow.md`:** mobile navigation parity, empty-space and settled-reveal review, content language follows the prompt.
